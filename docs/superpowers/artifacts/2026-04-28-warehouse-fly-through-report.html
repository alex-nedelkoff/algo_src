TL;DR

Wins

  • Trained MoE generalist drops into the warehouse env zero-shot and reliably passes 2 / 5 gates across 10 spawn-perturbed seeds
  • Hybrid env design works: numpy_quad dynamics + PyBullet wall-collision queries, with WarehouseRaceEnv as a clean GateRaceEnv subclass (~190 lines)
  • End-to-end deliverable: shareable .rrd recording with synced 3D-orbit + locked first-person views in rerun
  • 37/37 tests pass; complete pipeline (load checkpoint → instantiate env → predict → step → terminate → aggregate) verified by an integration smoke

Gotchas

  • PyBullet's loadURDF treats fixed-base meshes as closed solids — every interior point reports a (false) penetration. Fix: bypass URDF and build collision shape directly with GEOM_FORCE_CONCAVE_TRIMESH
  • Old MoE checkpoint expects 28-dim obs, current env emits 33-dim (formula was incremented post-checkpoint). Solved without re-training via a legacy_obs_v1=True slice mode
  • PyBullet's performCollisionDetection caches state across calls within one client → consecutive episodes diverge with identical spawns. Fix: rebuild env (= fresh client) per episode
  • expand_moe.py saves 5-expert weights but leaves the data dict's n_experts=4 → SB3's default PPO.load mis-shapes the policy. Use the repo's CorvidxPPO wrapper's strict=False path
  • Action mode for the checkpoint is TRPY, not MOTOR_RPM as remembered — easy to mis-set during eval setup

Barriers

  • Policy never gets past Gate 2 → Gate 3 transition. Wall hit at the same spot in all 10 seeds. Domain shift (warehouse inter-gate distances ~5–7 m exceed 5 m training arena) likely culprit
  • WarehouseRaceEnv is single-env only (n_envs=1); multi-env would need either separate PyBullet clients or multiple drone bodies in one client. Sufficient for sequential eval but blocks fine-tuning at scale on this env

Context

Why this matters

COR-95 produced the warehouse asset pipeline (URDF + 5 gates in PyBullet world). COR-96 produced a grey-box dynamics fitter. Both were enabling work without a closed-loop demonstration. This issue closes the loop: take our trained MoE generalist (5 experts, 7.7 gates / 6% crash on golden set), drop it into the warehouse with ground-truth gate observations, and measure how it does. Privileged-gate means no perception or SLAM in the loop — gate poses are read directly from the asset's gates_enu.json.

This is the prerequisite for adding perception. Without a known-good reference run, a perception-pipeline regression would be impossible to localize.

Technical background

  • Existing env — GateRaceEnv takes a Track (ordered GateState list), a VehicleParams, and a NumpyQuadDynamics backend. Pure-numpy, no physics engine.
  • Existing policy — expanded_5expert_v3/model.zip, MoE PPO with 5 experts × 128 dim, top-2 router. Trained 20M timesteps Mar 30 2026 on procedural tracks with TRPY action mode.
  • Warehouse asset — 5 gates around a ~17 × 15 m warehouse mesh; floor at z = -5.70 in the raw frame, gates at z ≈ -3.0 to -3.5.
  • Approach — wrap warehouse gates as a Track, subclass GateRaceEnv with PyBullet wall-collision detection. Reuse everything else.

  1. 1
    Track loader: gates_enu.json → Track
    Added load_warehouse_track(path, order=None, reorient_to_racing_line=False) in sim/tracks/__init__.py. The reorient flag overrides the JSON's authored gate yaws (which point inward to the warehouse interior, not toward the next gate) with a yaw computed as atan2(d_next.y, d_next.x) — matches the procedural-track-trained MoE's distribution. 4 unit tests.
  2. 2
    Hybrid env: WarehouseRaceEnv(GateRaceEnv)
    Boots pybullet.DIRECT, loads warehouse mesh + drone sphere, kinematically syncs drone position each step(), sets terminated[0] = True on contact. Disables arena bounds (warehouse mesh is the new boundary). World-offset translates both gates and mesh so the warehouse floor sits at z = 0 — lets GateRaceEnv's ground-termination check still work.
  3. 3
    Concave-mesh fix (PyBullet's loadURDF was treating walls as a solid blob)
    First contact-detection sweep reported penetration at every cell in the warehouse interior. Diagnosed as loadURDF defaulting to convex-hull collision for fixed-base meshes. Switched to p.createCollisionShape(GEOM_MESH, fileName=..., flags=GEOM_FORCE_CONCAVE_TRIMESH). After fix: clean spawn locations have zero contacts, inside-the-wall cells correctly fire.
  4. 4
    28-dim obs slice for the older MoE checkpoint
    Checkpoint expected 28-dim, current env emits 33-dim. Git-archaeology pinned the difference: commit 0a70b8c (Apr 2 2026) added per-gate width + height + arena_extent (5 extra dims). Added a legacy_obs_v1=True mode that slices current[0:24] ⊕ current[26:30] — bit-equivalent to what the checkpoint trained on. 4 unit tests including a value-equality check vs the unsliced obs.
  5. 5
    End-to-end smoke: load checkpoint, predict, step
    scripts/_warehouse_eval_smoke.py does one deterministic rollout from the canonical spawn. First attempt failed with SB3 shape mismatch on policy load (4-expert default vs 5-expert checkpoint). Worked around by using the repo's CorvidxPPO wrapper, which has a strict=False weights-only path that handles the expand_moe.py'd checkpoint. Smoke result: 2 gates passed in 283 steps, wall hit between Gate 2 and Gate 3.
  6. 6
    Eval CLI with multi-seed aggregation
    benchmark/warehouse_eval.py — argparse CLI, per-episode clean-spawn rejection sampling, deterministic rollout, aggregates gates_passed mean ± std + termination breakdown. JSON dumps for both summary and full trajectories. Discovered mid-task that PyBullet's broadphase cache state leaked across episodes within one client → same spawn / different seed gave different outcomes. Fix: rebuild the env per episode.
  7. 7

    Eval CLI extended to dump per-step quaternions. Replay script logs warehouse mesh + gate frames as static, drone pose + trail polyline + reward / action time-series per step. Two views in one blueprint: Spatial3DView for orbit, Spatial2DView rooted at /world/drone/fpv for locked FPV. Iterated body→camera rotation matrix three times to dial in the orientation.

Takeaways & Decisions

GO

Ship the privileged-gate harness as the reference baseline for the perception arc. Plumbing is correct end-to-end, results are deterministic and reproducible, and the eval CLI gives clean numbers to regress against.

NO-GO

Don't ship "the warehouse demo" as a customer-facing video yet — only 2/5 gates is below the ≥3-gate Target bar. Worth a small fine-tune (1–2M timesteps on warehouse + procedural mix) before publishing.

Analysis

  • The 2-gate ceiling is consistent across all 10 seeds. Same wall, same termination point. This is a behavior-failure (policy doesn't know how to make this turn), not a noise-failure. Fine-tuning on warehouse-like geometry should fix it cheaply.
  • Domain shift is the suspected root cause. Warehouse inter-gate distances peak at ~7 m vs 5 m training arena. The Gate 2 → Gate 3 transition (5.15, -2.5) → (5.15, -9.0) is a 6.5 m straight at sustained speed — out of distribution.
  • The legacy_obs_v1 slice was a 30-line patch instead of a checkpoint retrain. Worth keeping as a general pattern: when an old checkpoint mismatches the current obs format, slice down rather than retrain. Documented the 24-dim → 28-dim → 33-dim history so a future contributor can navigate it.
  • PyBullet broadphase cache leaks across episodes. Adds ~100 ms per-episode startup cost (rebuild client) but guarantees determinism. Acceptable for eval; would matter for fine-tuning where you run 100k+ episodes.
  • Two PyBullet quirks worth knowing. Concave-mesh-as-solid (use GEOM_FORCE_CONCAVE_TRIMESH) and broadphase cache (rebuild client). Saved both to memory under reference_* entries so the next contributor doesn't re-discover.

Summary

Delivered a full privileged-gate fly-through harness: warehouse env (WarehouseRaceEnv) wraps the trained MoE policy with PyBullet wall-collision detection, eval CLI runs N spawn-perturbed episodes and reports gates / crash-rate / lap-time, and a rerun replay produces a shareable .rrd with synced 3D-orbit and locked-FPV views. Zero-shot the trained generalist passes 2 / 5 gates across all 10 seeds, terminating consistently at the same wall between Gate 2 and Gate 3 — a behavior-failure rather than noise. Hits the MVP success bar but misses the ≥3-gate Target. Next step is a small warehouse-fine-tune to lift the score, then start the perception arc (camera → GateNet → PnP → policy) against this baseline.
